## Protection and corrections

New Nextcloud photo filenames are marked as replaceable placeholders. Legacy
`preserved` captions are not guessed from `.jpg` or any other text pattern.
This also protects historical empty `preserved` captions unless replacement is
individually confirmed; new opted-in empty uploads have explicit pending provenance.
Manual captions, including explicitly saved empty text, stay protected; manual
identifications are skipped in the selected-photo workflow. Manual tags and tag
suppression survive analysis.

Only captions generated by this workflow are subsequently rewritten by reference,
session, platform, series or event-context corrections. Existing recognition is
reused; there is no new recognition request or caption language-model request.
Independent safety review is not disabled by this reuse. Conflicting reference
identity is never copied. Automatic captions include only safely number-backed
reference vehicles; unknown vehicles neither inherit their information nor
suppress other valid matches. Without a safe match, the caption stays context-only.
Compatible literal manufacturer branding and a unique complete team core with
terminal organisational suffixes (e.g. Bleu Mercure / Bleu Mercure Esport) do not
veto a number-backed match. Arbitrary sponsor strings, differing teams, ambiguous
short names and incompatible models still veto. Driver names are the registered lineup for the number, never a claim
about a pictured/physically driving person. Captions place names directly after
the vehicle, without a lineup prefix: `#007 North Racing — Porsche 911 — A. One / B. Two`.
The same formatting applies to manual number-assignment previews and saves and
caption suggestions. Missing drivers add no separator; exceeding the 1000-character
limit falls back to event context rather than cutting a lineup. This format change
does not clean up stored captions or change provenance/replacement protections;
it applies only when captions are subsequently generated through the normal flows.

Disabling matching fences queued/in-progress automatic writes and preserves saved
results. Re-enabling does not scan history; explicit selection can reuse stored
recognition. Editor edits made while a worker is processing are read again under
locks before saving, so confirmed historical replacement cannot win over a later
manual caption edit.
