Change of plan: We do NOT need to migrate existing media to Cloudflare R2.

The VCO Content Database is not yet actively used, and I explicitly approve launching with an empty media library, without the existing gallery photos and videos.

Please simplify the R2 implementation accordingly.

New objective

Use Cloudflare R2 as the primary storage provider for all NEW media uploads, with separate Development and Production buckets.

* Development: vco-content-media-dev
* Production: vco-content-media

Requirements

1. Stop work on the existing-media migration, copy-only pilot and legacy-object reconciliation. These are no longer launch requirements.
2. Preserve existing users, events, settings, AI functionality and other non-media data.
3. Audit existing media references and propose the minimum safe reset needed for an empty media library. Do not delete any database records or storage objects without separate approval.
4. Configure all new photo, video, thumbnail and poster uploads to use R2.
5. Preserve the existing image quality, file-size limits, Creator quotas, access controls, download statistics and AI processing.
6. Keep both R2 buckets private.
7. Maintain the existing secure delivery architecture for previews and protected downloads.
8. Ensure Development uses only Development credentials and Production uses only Production credentials.
9. Perform a small Development smoke test using newly created test media:
    * Upload and display one photo
    * Generate and display its preview
    * Upload and play one video
    * Verify protected access
    * Verify AI processing where practical
    * Verify test-object cleanup
10. Avoid unnecessary migration infrastructure, duplicate storage logic and extensive legacy-media testing.

Important

Do not switch Production storage, reset the media database, delete existing objects or deploy without my explicit approval.

First report:

* The simplest implementation path
* Any blockers to starting with an empty media library
* Required Production secrets/configuration
* The minimal Development smoke-test plan

Prioritize getting the new R2-based media platform ready for launch rather than preserving media we no longer need.
