# VCO Content Database – Complete Transactional Email System

## 1. Objective

Establish a consistent, professional and scalable transactional email system for the VCO Content Database.

The existing branded verification email has already been designed and tested visually. Use this approved template as the foundation for all future system emails.

The goal is to deliver a premium VCO-branded communication experience for:

- Registered users
- Community Creators
- Account security
- Gallery publishing
- Future community interactions
- Future Credit purchases and Creator monetization

**Important: Inspect the existing implementation first. Reuse working code and introduce only necessary changes.**

Do not build a complex email marketing platform or notification management system.

---

# 4. Email Catalogue – Phase 1

Implement or reuse the following transactional emails where the corresponding application functionality exists.

All copy should use British English.

## EMAIL 01 – Email Verification

**Trigger:** A user registers and must verify their email address.

**Subject:**
Verify your email | VCO

**Headline:**
ONE CLICK. YOU'RE IN.

**Body:**

Welcome to the VCO Content Database.

Verify your email address to activate your account and get started.

**CTA:**
VERIFY EMAIL

**Additional text:**

This verification link expires after 60 minutes and can only be used once.

If you did not request registration, you can safely ignore this email.

**Fallback:**

Button not working?

Copy and paste the verification link into your browser:

[Verification URL]

### Rules

- Preserve existing token generation and validation.
- Preserve actual expiry and single-use behaviour.
- Do not hardcode a 60-minute expiry if the backend differs.
- Do not expose verification tokens in logs.
- Do not modify the working verification workflow unnecessarily.
- Do not send a separate welcome email until verification succeeds.

## EMAIL 07 – Media Processing Failure

**Trigger:** A Creator upload or AI processing operation reaches a final failure state requiring user action.

**Subject:**
Action needed for your VCO upload

**Headline:**
SOMETHING NEEDS YOUR ATTENTION.

**Body:**

We couldn't complete processing for some of your uploaded content.

Your successfully stored photos remain available.

Open Creator Studio to review the affected items and try again where appropriate.

**CTA:**
REVIEW UPLOAD

**Additional text:**

If the issue continues, please contact VCO support.

### Rules

- Do not send emails for temporary processing errors.
- Do not send during automatic retries.
- Send only for final, actionable failures.
- Avoid sending one email per failed image in a large batch.
- Prefer one notification per affected upload batch.
- Do not claim that a file was preserved unless that is confirmed.
- Reuse existing final-failure events if available.
- If no reliable final-failure trigger exists, keep this template prepared but inactive.

# 7. Trigger and Delivery Architecture

Use the existing application architecture.

Requirements:

- Send emails only for confirmed events.
- Avoid duplicate delivery caused by retries or repeated requests.
- Use stable event or transaction identifiers where available.
- Do not introduce unnecessary background services.
- Reuse existing job infrastructure if asynchronous sending is required.
- Log delivery status without exposing sensitive tokens.
- Distinguish provider acceptance from confirmed delivery.
- Handle provider failures gracefully.

Email failures must not corrupt account, gallery or payment state.

Do not introduce a large notification event framework solely for these templates.

# 9. Security and Privacy

- Use the existing Resend integration.
- Use the configured RESEND_FROM value.
- Never hardcode API keys.
- Never expose secrets in logs or reports.
- Use the trusted PUBLIC_SITE_URL for application links.
- Validate redirect destinations.
- Preserve existing verification and password reset security.
- Never include passwords in emails.
- Never include private account information unnecessarily.
- Do not expose protected download URLs.
- Do not add third-party tracking pixels.
- Avoid leaking sensitive authentication links through analytics or redirect services.
- Keep account existence private where appropriate.

For verification and reset links, preserve the existing secure token handling and actual expiry rules.
