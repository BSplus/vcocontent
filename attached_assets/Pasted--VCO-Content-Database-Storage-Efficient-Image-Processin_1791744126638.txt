# VCO Content Database – Storage-Efficient Image Processing

## Objective

Optimize image storage for the VCO Content Database while maintaining professional download quality and keeping total storage costs under control.

**First inspect the existing implementation. Reuse existing functionality and make only necessary changes.**

## 1. Image Storage Strategy

Store a maximum of two image files per media item:

**A. High-Res Download**
- Maximum file size: 5,000,000 bytes (5 MB).
- Preserve the highest practical image quality and resolution within this limit.
- Do not automatically limit all images to 2560 pixels.
- Prefer quality optimization before reducing dimensions.
- Never upscale smaller images.
- Do not increase file size unnecessarily.
- Use a suitable output format (JPEG or WebP) based on quality, compatibility and storage efficiency.

**B. Web Preview**
- Maximum file size: 100 KB.
- Optimized for fast gallery browsing.
- Target approximately 640 pixels on the longest edge, as currently implemented.
- Reuse existing thumbnail generation.

Do not store additional redundant image variants.

## 2. Official VCO Images

For Nextcloud imports:

- Source originals may exceed 5 MB.
- Keep original files unchanged in Nextcloud.
- Store only the optimized High-Res version and web preview in the VCO Content Database.
- Do not duplicate large originals in application storage.
- Preserve the Nextcloud source reference where available.
- Never modify or delete the Nextcloud source.

The application must not depend on Nextcloud being available for normal image browsing or optimized High-Res downloads.

## 3. Community Creator Images

For Creator uploads:

- Maximum original upload size: 5,000,000 bytes.
- Preserve the uploaded file byte-for-byte as the downloadable original.
- Generate one separate optimized web preview.
- Do not recompress or resize the Creator's downloadable original.
- Maintain the existing Creator Free storage, gallery and photo quotas.

For storage accounting, avoid double-counting files while consistently including stored previews in the total quota.

## 4. Quality and File Size

Avoid excessive compression.

Use an efficient image optimization strategy that:

- Preserves original dimensions where practical.
- Reduces image quality moderately before reducing resolution.
- Maintains a sensible minimum visual quality.
- Handles photographs with high detail, motion and complex textures.
- Avoids repeated recompression of previously optimized images.
- Never silently produces severely degraded downloads.

If acceptable quality cannot be achieved below 5 MB, report the trade-off instead of silently applying extreme compression.

## 5. Download Behaviour

Clearly distinguish:

- **VCO:** High-Res Download (optimized, maximum 5 MB)
- **Creator:** Original Download (uploaded file, maximum 5 MB)

Preserve existing authentication, download tracking, premium restrictions and access controls.

Do not expose protected downloads through unrestricted public storage URLs.

## 6. Existing Media

- Do not delete or overwrite existing media.
- Do not automatically reprocess the entire library.
- Do not initiate bulk Nextcloud imports.
- Identify whether existing images can be improved through a later controlled reimport.
- Preserve all metadata, AI tags, captions and gallery assignments.

## 7. Focused Validation

Before implementing a broader change, compare a small set of representative images using the existing processing pipeline and the proposed approach.

Report:

- Source dimensions and file size
- Resulting High-Res dimensions and file size
- Preview file size
- Estimated storage impact
- Any visible quality compromises

Use existing development fixtures or authorized samples.

Avoid expensive or extensive benchmark suites.

## 8. Implementation Rules

- Inspect first.
- Reuse the existing storage and processing architecture.
- Keep the solution simple.
- No additional storage services.
- No unnecessary database migrations.
- No new background workers.
- No changes to video processing.
- No production deployment or bulk reprocessing without explicit approval.

## 9. Final Report

Provide a concise summary of:

1. Existing implementation and identified issues
2. Proposed or implemented changes
3. Image quality versus storage trade-offs
4. Storage requirements per image
5. Impact on existing VCO and Creator media
6. Remaining limitations

**Priority: Professional-looking downloads, fast browsing and predictable storage costs — without unnecessary technical complexity.**
